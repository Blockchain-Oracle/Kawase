## La estructura

```text
 iPhone / Android / Web (Expo 57)          LiveKit Cloud (WebRTC)
        │  chat (SSE), pantallas                    │ audio
        ▼                                          ▼
 ┌──────────────────────────────┐        ┌───────────────────────┐
 │ apps/api — Hono en Node      │◀──────▶│ apps/voice-agent      │
 │  turno del agente (AI SDK 7) │  turno │  trabajador de LiveKit Agents │
 │  políticas · intenciones · ejecutores │        │  STT → turno → TTS      │
 └──────┬───────────┬───────────┘        └───────────────────────┘
        │           │
        ▼           ▼
   Postgres     Arc (Red principal / Red de pruebas) · Circle (App Kit, CCTP, billeteras, faucet) · Privy
```

## Un solo cerebro

`agentTurn()` en `packages/agent` sirve tanto para **chat** como para **voz**: el trabajador de voz envía lo que escucha al mismo turno,
con las mismas herramientas, límites e hilo. El modelo (OpenAI `gpt-5.6-luna` de forma predeterminada, elegido mediante un registro de modelos) solo
**propone**: ninguna herramienta recibe una red, una dirección o una opción de «aprobar». El código resuelve el destinatario, ejecuta la política, crea
la transacción y la ejecuta.

## Política pura e intenciones explícitas

- `packages/policy` es una función pura que convierte hechos en resultados (errores, rechazos, requisitos previos, aclaraciones y advertencias),
  además de la **ruta**: la asignación o una firma de billetera. Se ejecuta al preparar una tarjeta, de nuevo al aprobar con hechos actualizados
  y otra vez al ejecutar.
- `packages/intents` define cada acción como un **borrador** versionado y con hash EIP-712 (`SendDraft`, `SwapDraft`, `BridgeDraft`,
  `EarnDraft`). Una aprobación indica la versión exacta que aprueba; cualquier cambio crea una versión nueva.
- **Resolver y continuar**: cuando falta algo (un contacto, una moneda o un inicio de sesión), la solución continúa la misma intención
  en lugar de empezar de nuevo.

## Rutas del dinero

- **Envíos con asignación**: se reserva el registro de gastos bajo un bloqueo por usuario y, después, la billetera del agente de Kawase (una billetera
  controlada por desarrolladores de Circle) canjea tu delegación; el registro `Transfer` del recibo se compara con el borrador.
- **Acciones firmadas con billetera** (por encima de la asignación, operaciones, puentes y generación de rendimiento): la API crea la transacción exacta. Para
  las operaciones de App Kit, se capturan y comprueban las llamadas del kit y, después, se agrupan en un solo lote propio EIP-7702. El dispositivo la firma
  con Face ID y la API verifica los bytes firmados contra el borrador antes de transmitirla.
- Los **puentes** se siguen en tres etapas: la quema en Arc, la atestación de Circle y la emisión en la cadena de destino.
- Las **Automatizaciones** se ejecutan en el ejecutor de la API cada 30 segundos: cada ocurrencia se reclama exactamente una vez, se vuelve a comprobar
  con hechos actualizados y se paga mediante la misma ruta de envío, generación de rendimiento o puente, usando la asignación propia de la automatización.
- **Idempotencia en todas partes**: se guarda una clave de idempotencia de Circle antes de llamar a Circle; las transacciones sin procesar guardan su hash
  antes de transmitirse; los resultados ambiguos se convierten en `unknown_outcome` y solo se vuelven a comprobar, nunca se vuelven a enviar.

## Datos

**Postgres 17 con Drizzle** es el único almacenamiento y el único bus de mensajes: una bandeja de salida escrita en la misma transacción que cada
cambio, `pg_notify` para distribuir eventos mediante eventos enviados por el servidor y una tabla de bandeja de entrada como fuente de verdad para
las notificaciones. El dinero se almacena como unidades base exactas (`numeric(78,0)`, `bigint` en TypeScript); los identificadores son UUIDv7.

## Monorepo

| Parte | Qué es |
|---|---|
| `apps/api` | API de Hono: autenticación, flujo de chat del agente, intenciones y aprobaciones, ejecutores, webhooks |
| `apps/mobile` | Expo 57 / React Native 0.86: la aplicación para iOS, Android y web |
| `apps/voice-agent` | Trabajador de LiveKit Agents (Node) |
| `apps/docs` | este sitio (Fumadocs 16, Next 16) |
| `apps/landing` | la página de presentación y el kit para jueces |
| `packages/config` | todas las constantes: límites, registro de capacidades, idiomas, voz y tiempos de espera |
| `packages/policy`, `packages/intents` | el motor de políticas puro y los borradores EIP-712 |
| `packages/integrations/*` | delegaciones (MetaMask Delegation Framework), Circle App Kit |
| `packages/networks`, `packages/money` | las dos redes de Arc y las direcciones verificadas; tipos de dinero exactos |
| `packages/identity` | logotipos reales con su procedencia |

## API pública

La API está en `https://api.getkawase.xyz`. Estos son los endpoints públicos que no requieren autenticación:

| Endpoint | Devuelve |
|---|---|
| `GET /health` | `{ ok, networks }` |
| `GET /capabilities` | el registro de capacidades con cambios durante la ejecución, por red |
| `GET /public/stats` | solo recuentos totales (envíos completados, operaciones, puentes, movimientos de generación de rendimiento, ejecuciones de automatizaciones y cuentas) |

Todo lo demás necesita una sesión (un token bearer de la aplicación o una cookie en la web).

## Alojamiento

Todo funciona en un servidor de **Coolify**, detrás de Traefik con Let's Encrypt: la API, la aplicación web, el trabajador de voz, esta documentación
y la página de presentación, además de Postgres. Cada servicio usa un Dockerfile creado desde la raíz del monorepo; los servicios escuchan en `::`
(las comprobaciones de estado de Coolify resuelven `localhost` como IPv6).

## Pruebas que lo demuestran

Se ejecutan en la red de pruebas de Arc con transacciones reales (`pnpm --filter @kawase/api test`): envíos (con asignación y firmados con billetera,
doble toque → un envío, firmas manipuladas rechazadas), operaciones, puentes (quema → atestación → emisión), depósitos y retiros de generación de rendimiento,
automatizaciones programadas, guardado automático, reglas y recuperación después de ejecuciones interrumpidas. El paquete de delegación demuestra
por sí solo los límites en cadena (`pnpm --filter @kawase/integrations-delegation test:arc-testnet`).
