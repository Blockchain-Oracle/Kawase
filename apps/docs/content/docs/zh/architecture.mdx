## 整体结构

[![Kawase architecture diagram: one app feeds a shared agent turn, voice runs through LiveKit, and the API executes through Arc and Circle](/media/architecture/architecture-v2.png)](/media/architecture/architecture-v2.png)

## 一个大脑

`packages/agent` 中的 `agentTurn()` 同时服务于**聊天**和**语音**：语音 worker 会把识别到的内容发送到同一个回合，
使用相同的工具、限额和线程。模型默认使用 OpenAI 的 `gpt-5.6-luna`，通过模型注册表选择。模型只能**提出建议**：
任何工具都不会接收网络、地址或“批准”标记。代码会解析收款人，执行策略，构建交易并执行。

## 纯策略，明确意图

- `packages/policy` 是一个根据事实生成结果的纯函数，结果包括错误、拒绝、前置条件、需要澄清的内容和警告，
  以及**路径**：额度授权或钱包签名。它会在卡片生成时运行，在批准时使用最新事实再次运行，并在执行时再次运行。
- `packages/intents` 将每个操作定义为带版本、经过 EIP-712 哈希的**草稿**（`SendDraft`、`SwapDraft`、`BridgeDraft`、
  `EarnDraft`）。批准时会指定批准的确切版本；任何更改都会生成新版本。
- **解析并继续**：当缺少某项内容（联系人、货币或登录状态）时，修复后会继续执行同一个意图，而不是从头开始。

## 资金路径

- **额度转账**：在每位用户的锁下预留支出账本额度，然后由 Kawase 的代理钱包（Circle 的开发者控制钱包）兑现你的授权；
  系统会将收据中的 `Transfer` 日志与草稿进行比对。
- **钱包签名操作**（超过额度、交易、跨链、赚取收益）：api 会构建精确交易——对于 App Kit 操作，系统会捕获并检查 kit
  的调用，然后将它们封装成一个 EIP-7702 自批处理交易——设备使用 Face ID 对其签名，api 会在广播前验证签名字节是否与草稿一致。
- **跨链**会分三步追踪：Arc 上的销毁、Circle 的证明，以及目标链上的铸造。
- **自动化**每 30 秒在 api 的执行器中运行：每次执行只会认领一次，使用最新事实重新检查，并通过相同的转账、赚取收益或跨链路径，
  使用自动化自身的授权额度完成支付。
- **全程保证幂等性**：调用 Circle 前会先存储 Circle 幂等键；原始交易会在广播前存储其哈希；结果不明确时会标记为
  `unknown_outcome`，只会重新检查，绝不会重复发送。

## 数据

**Postgres 17 搭配 Drizzle** 是唯一的数据存储和唯一的消息总线：每次变更都会在同一事务中写入 outbox，
通过 `pg_notify` 将事件分发到服务器发送事件中，并使用 inbox 表作为通知的事实来源。资金以精确的基础单位存储
（`numeric(78,0)`，TypeScript 中为 `bigint`）；ID 使用 UUIDv7。

## Monorepo

| 部分 | 内容 |
|---|---|
| `apps/api` | Hono API：身份验证、代理聊天流、意图与批准、执行器、webhook |
| `apps/mobile` | Expo 57 / React Native 0.86：iOS、Android 和 Web 应用 |
| `apps/voice-agent` | LiveKit Agents worker（Node） |
| `apps/docs` | 本网站（Fumadocs 16、Next 16） |
| `apps/landing` | 展示页和评审工具包 |
| `packages/config` | 所有常量：限额、能力注册表、本地化、语音、超时设置 |
| `packages/policy`、`packages/intents` | 纯策略引擎和 EIP-712 草稿 |
| `packages/integrations/*` | 授权（MetaMask Delegation Framework）、Circle App Kit |
| `packages/networks`、`packages/money` | 两个 Arc 网络和经过验证的地址；精确的资金类型 |
| `packages/identity` | 带来源信息的真实 logo |

## 公共 API

api 地址为 `https://api.getkawase.xyz`。公开且无需身份验证的端点：

| 端点 | 返回内容 |
|---|---|
| `GET /health` | `{ ok, networks }` |
| `GET /capabilities` | 按网络返回包含运行时覆盖项的能力注册表 |
| `GET /public/stats` | 仅返回汇总数量（已完成的转账、交易、跨链、赚取收益操作、自动化运行次数、账户数） |

其他所有内容都需要会话（应用提供的 bearer token，或 Web 上的 cookie）。

## 托管

所有服务都运行在 Traefik 后、使用 Let's Encrypt 的 **Coolify** 服务器上：api、Web 应用、语音 worker、本文档、
展示页以及 Postgres。每个服务都从 monorepo 根目录通过 Dockerfile 构建；服务监听 `::`
（Coolify 的健康检查会将 `localhost` 解析为 IPv6）。

## 证明系统可靠性的测试

在 Arc 测试网上使用真实交易运行（`pnpm --filter @kawase/api test`）：转账（额度授权和钱包签名、
双击 → 一次转账、拒绝被篡改的签名）、交易、跨链（销毁 → 证明 → 铸造）、赚取收益的存入和提取、
定时自动化、自动储蓄、规则，以及中断运行后的恢复。授权包会单独证明链上限额
（`pnpm --filter @kawase/integrations-delegation test:arc-testnet`）。
