## What the concern gets right

There is a recurring narrowing pattern. The underlying code often works for an initial case, but the user-facing feature needs a larger contract:

| Initial slice | Full responsibility that remains |
|---|---|
| Automation occurrence claimed once | Interrupted occurrence resumes and reaches a truthful outcome once |
| A send screen exists | Exact amount, correct authority, immutable review, unknown outcome, recovery and receipt |
| Other markets appear in a list | Supported read-only discovery, clear execution eligibility and complete market inventory |
| A broad capability is “shipped” | Specific action/asset/network/provider availability is accurate |
| Logo acquired or card drawn | Correct identity roles on each screen; actual provider/lifecycle behind the artwork |
| Native journey demonstrated | Other platforms, interruptions, inaccessible/error states, deployment and mainnet evidence |

The evidence does not establish that the builder deliberately forgot the full product. Many remainders are explicit stages or blockers. However, stale status records and broad completion labels make it too easy for those remainders to disappear from the next session's attention.

## The handoff rule that prevents repetition

For every approved promise, keep one current row:

`Decision/source → flow/reference ID → implementation → supported actions/modes/platforms → recovery → evidence revision → remaining work → owner/dependency`

Use separate states for planned, blocked, implemented, accepted and deployed. A later stage is an order of work, not an exclusion. An actual user exclusion stays excluded. A screenshot proves the captured visual state; a finalized transaction proves that specific lifecycle; neither proves all related branches.

After each slice, update the status, stage record, capability/parity row and acceptance evidence together. Preserve open work in a visible queue with its dependency. That gives the next agent a reliable reminder and gives the user a clear view of the complete product.
