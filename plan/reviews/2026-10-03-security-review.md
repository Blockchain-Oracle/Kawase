## Low

- Practice mode's regex (`app.ts:345`) misses `/crosschain`, `/lend`, the withdrawal batch, `/business/payouts`, margin protection — A3.
- Automated margin closes ignore pause and practice mode (`protection.ts:256-302`) — B1. **Merged `da2c8e6`.** Rule: practice mode never touches real money (a hit target is only told, once; the position stays watched); pause allows risk-reducing closes only (a stop-loss still closes, a take-profit waits and is told once). Test: `margin-protection-mainnet.test.ts`.
- `pendingRelays`/`pendingTransactions` never expire; a double `submitRelayedBatch` makes the relayer pay for a reverted call — B2. **Fixed in B2 branch (with H5):** both expire (relay TTL / 15 min), a request is claimed before any await and a second submit gets the first answer, and every relayed batch is simulated before it is sent.
- A webhook with a random `X-Circle-Key-Id` triggers an authenticated Circle fetch with the live key (`onramp/service.ts:259-268`) — B1. **Merged `da2c8e6`.** known keys stay cached; ids that aren't short and URL-safe are never looked up; new ids at most 6 a minute across everyone; an id Circle 404s is not asked again for an hour (bounded); 5 s fetch timeout. Test: `onramp-webhook-keys.test.ts`.
- Voice token key derived from the LiveKit secret; the token survives sign-out for 30 minutes — lane C (later).
- A renamed @handle is free to take immediately; registering someone's push token removes it from their device — B2. **Fixed in B2 branch:** a handle given up (renamed or cleared) is held 30 days for everyone but its last owner (`handle_holds.user_id`, migration 0081; `test/handle.test.ts`); a push token moves only from the same person's other device, the same installation, or a phone no one is signed in on (otherwise 409, theirs keeps it), and sign-out lets the token go (`test/security-push-token.test.ts`).

## Plausible, verify

- **SSRF through x402 catalog listings** (`discovery.ts:54-79` accepts `http:`, private IPs, host templates; `pay.ts:86` fetches) — B2: require https, reject templates, block private addresses at connect time. **Fixed in B2 branch:** `integrations-x402/src/guard.ts` — listings must be https with the host written out (no `{param}` in scheme/host/port, no credentials, no private IP or local name) or they are dropped from the catalog; sellers are called through `sellerFetch`, which resolves the host and connects only when every address is public (node http(s) `lookup` hook, so rebinding cannot slip past) and refuses redirects; only the configured demo seller origin is exempt (`test/security-ssrf.test.ts`; `marketplace-practice` passes against the live demo seller).
- **Rate limits keyed on the first `X-Forwarded-For`** — checked by the lead 10-03: Traefik replaces the spoofed header with the real peer IP, so not spoofable. The bucket map never shrank; fixed by sweeping idle buckets (`rate-limit.ts`).
- **Turnkey email trust** — **confirmed and fixed by the lead 10-03.** Turnkey's `UPDATE_USER_EMAIL` takes `verificationToken` as optional, so a user could set any email on their own sub-org; Kawase copied it on every sign-in and in `syncEmail`. `TurnkeyReader.getUser` now returns an email only if it was never changed since the Auth Proxy set it at sign-up, or if the user's latest completed change carried a verification token (`emailIsProved`, `apps/api/src/auth/turnkey.ts`; unit test `turnkey-email.test.ts`; checked read-only against three real sub-orgs).
- **Whether models follow the injection in H2** — code path confirmed, model behaviour untested (OpenAI credit is out).
