Code: `plan/spikes/code/10-better-auth/` (`./run.sh` = fresh server + headless test; `node test-passkey.ts` = Chrome with a virtual authenticator; device screen `mobile-spike-auth.tsx`, run from a temporary route that has since been removed from `apps/mobile`). Screenshot: `code/10-better-auth/ios-phase2.png`.
Date: 2026-09-30
**Result: PASS.** Headless 18/18, web passkey 4/4, iOS simulator (Expo 57 / RN 0.86.3 dev build) guest → email OTP upgrade with the data kept, and the session restored after an app restart. **Not tested: passkeys inside the native app** (see finding 6).

Docs read first: Better Auth `plugins/anonymous`, `plugins/email-otp`, `plugins/passkey`, `integrations/expo`, `integrations/hono`, `adapters/drizzle`, `concepts/database` (github.com/better-auth/better-auth `docs/content/docs/`, fetched 2026-09-30).

## Setup that worked
- `better-auth` 1.7.6 + `@better-auth/expo` 1.7.6 + `@better-auth/passkey` 1.7.6, Drizzle adapter (`drizzle-orm` 0.45.3, `pg`), mounted on Hono with `app.all('/api/auth/*', (c) => auth.handler(c.req.raw))`.
- Plugins: `expo()`, `anonymous({ onLinkAccount })`, `emailOTP({ sendVerificationOTP })`, `passkey({ rpID, rpName, origin })`.
- Schema: `npx auth@latest generate --config ./auth.ts --output ./auth-schema.ts` (the CLI is now the `auth` package; `@better-auth/cli` stops at 1.4.x).
- App client: `createAuthClient` from `better-auth/react` with `expoClient({ scheme: 'kawase', storagePrefix: 'kawase', storage: SecureStore })`, `anonymousClient()`, `emailOTPClient()`. Native deps: `expo-secure-store`, `expo-network` (both installed with `npx expo install`; they need a native rebuild).

## Results
- **Guest upgrade keeps data.** A guest signs in with `signIn.anonymous()`, creates rows, then signs in with email OTP while still holding the guest session. `onLinkAccount` fires once, our callback moves the rows to the new user, and Better Auth deletes the guest row. Verified headless, in Chrome, and on iOS.
- **Merge into an existing account works the same way.** A guest on a second device who signs in to an existing email is merged into that account (3 rows under one user id).
- **A failed migration loses nothing.** When `onLinkAccount` throws, the sign-in returns 500, the guest row and its data stay, and the session stays the guest's. The new (empty) account row already exists at that point, so a retry takes the "existing account" path and completes the move. Verified (checks 8, 8b).
- **Wrong codes:** `INVALID_OTP` three times, then `TOO_MANY_ATTEMPTS`; the real code is dead afterwards.
- **iOS:** the session cookie is stored in SecureStore (`authClient.getCookie()`), app requests send it as a `Cookie` header with `credentials: 'omit'` through `expo/fetch`, and after killing and relaunching the app `getSession()` returns the upgraded account with no sign-in.
- **Web passkey** (real Chrome, CDP virtual authenticator): register, sign out, `signIn.passkey()` returns the same user and data.

## Findings (these shape Stage 3)
1. **`onLinkAccount` must move every user-owned table, and passkeys too.** Better Auth deletes the guest row after the callback, and our tables reference `user.id` with `ON DELETE CASCADE`, so anything not moved is deleted. Do the moves in one transaction. A passkey added while still a guest is cascade-deleted with the guest and leaves a dead credential on the device (`PASSKEY_NOT_FOUND`); moving the `passkey` rows in the callback fixes it (verified). Simpler product rule on top: offer "add a passkey" only after the upgrade.
2. **Better Auth 1.7 refuses cookie-bearing POSTs with no `Origin` header** (`MISSING_OR_NULL_ORIGIN`), and refuses untrusted origins (`INVALID_ORIGIN`). Browsers send `Origin`; the Expo client sends `expo-origin: kawase://`, which the `expo()` server plugin accepts when `kawase://` is in `trustedOrigins`. Server-to-server callers (the voice agent, tests) must send an `Origin` or use a bearer/API path instead of cookies.
3. **IDs:** `advanced.database.generateId: () => uuidv7()` gives UUIDv7 ids, but the CLI then generates `text` id columns. With `generateId: 'uuid'` the CLI generates `uuid` columns and lets Postgres create v4 ids. To keep "UUIDv7 generated by the app" with real `uuid` columns, generate the schema in `'uuid'` mode and run with the function (not tested together; check in Stage 3), or accept `text` ids for the five auth tables.
4. A guest cannot create a second guest (`ANONYMOUS_USERS_CANNOT_SIGN_IN_AGAIN_ANONYMOUSLY`), and `POST /delete-anonymous-user` removes a guest and its rows ("discard and start over").
5. Guest emails are placeholders (`temp-…@guest.kawase.invalid` via `emailDomainName`); never send mail to them.
6. **Passkeys in the native app are an open item.** `@better-auth/passkey`'s client uses the browser WebAuthn API (`@simplewebauthn/browser`), which React Native does not have. Native passkeys need a native module (candidates on npm: `expo-better-auth-passkey` 1.5.1, `react-native-nitro-better-auth-passkey` 2.0.5, not evaluated) plus an associated domain: the api's HTTPS domain must serve `/.well-known/apple-app-site-association` and be the `rpID`. That needs the api deployed first. Until then the app uses email OTP, the same fallback the plan already uses for the desktop shell.
7. The same authenticator cannot be registered twice for one user (`ERROR_AUTHENTICATOR_PREVIOUSLY_REGISTERED`); show that as "this device already has a passkey".
8. Device-test lesson: `useLocalSearchParams()` can be empty on the first render after a deep link. A screen that acts on a param must wait until the param is present.

## Decision
Keep Better Auth 1.7.6 with anonymous + email OTP + passkey (web now, native later) + expo. Put the guest migration in one function in `packages/db` that lists every user-owned table, called from `onLinkAccount` inside a transaction, with a test that fails when a new user-owned table is not on the list.
