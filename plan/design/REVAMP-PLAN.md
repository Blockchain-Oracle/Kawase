# Kawase UI revamp — "Lime on Ink"

## Context

Abu did not like the colours and the design intention of what has been built so far (Koe: a near-black stage, amber, the orb as a dedicated screen). He commissioned a reference study of three mobile apps — Solflare, Phantom and Fomo — from screen recordings (`docs/design/reference-study-2026-09-30/`, by Codex: 97 screens, 18 motion clips, 44 component briefs, 38 identity entries, 116 feature entries, 18 redesign ideas) and asked for the UI to be revamped from it, without letting anything built so far hold the redesign back (D34). Real logos and artwork are a firm requirement.

What stays: the product decisions (D33 wallet: email code / Apple / Google sign-in, no PIN, a daily allowance, Face ID above it; D15 network toggle; D31 notifications), the stages of the master plan, the api (live), the Turnkey sign-in, the wallet setup/allowance flows, the i18n catalogs and the right-to-left machinery, the pnpm/Expo/Uniwind/RNR/21st.dev stack. What changes: the visual identity, the materials and artwork, the navigation shell, the motion grammar, and every screen.

Abu's answers while planning (2026-09-30): direction **Lime on Ink**; **optional @handle** in onboarding; the **orb stays as the voice symbol, re-made** in the new material and used as an overlay over the live page.

Outcome: an app that looks and moves like the references (story onboarding with layered art, textured black cards, glass dock, blur overlays, real logos everywhere, memorable completion moments) while staying Kawase (voice-first money agent on Arc, 10 languages, testnet/mainnet, allowance + Face ID).

## The product this design serves (form factors and the map)

Kawase is one product on four form factors, and the design system has to hold all of them: the **phone** (iOS dev build and Android APK — the primary form factor, voice-first, Face ID/biometrics, QR scanning, push, Live Activity), the **web app / PWA** (the only way iPhone users and judges reach a wallet app under D10; server-rendered, keyboard-first, QR shown instead of scanned), the **desktop** (PWA / Tauri shell, Stage 13: the dock becomes a rail, ⌘K palette), and **voice** (Stage 10: the orb overlay, captions, cards pushed mid-conversation, no-mic completion of every flow). The docs site and the landing page (Stages 14/15) reuse the same identity and web components. Both consumer and business users (D11) use the same app; business surfaces (invoices, payroll, vendor labels) arrive in Stages 5/8 on the same card base.

## What is on every screen (cross-cutting, from the first panel)

- **Language**: a language pill sits top-end on the **first onboarding panel** and on every onboarding screen (story, sign-in sheet, handle, setup, completion), on guest home, and in Settings. Auto-detected from the device on first run (A4); one tap opens the language sheet (each language in its own name and script); the change is instant — text, direction (Arabic/Urdu flip to RTL without a restart, already built), number and date formats, and later the agent's replies and voice (K6). The same pill never disappears because the user signed in.
- **Network**: the network pill in the header **is the toggle** (D15, A3): one tap switches mainnet ↔ testnet, instant both ways; the first switch to mainnet raises the consent sheet; the testnet strip, the pill and the TESTNET / REAL MONEY eyebrows are the three redundant indicators (never colour alone); every money card, sheet, receipt and QR names the network; new users start on testnet. Settings → Network repeats the toggle with the explanation, it is not the only place.
- **Typing**: every voice surface has the keyboard button visible; every voice action has a tap equivalent (K4, U1).
- **Blocker as label** (S5, T1): a disabled primary button names the first fixable reason ("Above your allowance — Face ID", "Not enough USDC for fees — top up", "Mainnet only — switch network"), the same words in UI, chat and voice.
- **Back and dismiss**: pushed pages have a back chevron; sheets have a grab handle and a scrim tap; nested sheets have an explicit back; overlays have ×; Android hardware back follows the same order; values survive a return (S7-style retention).
- **Keyboard-aware primary action** on every form (code, handle, amount, search, memo).
- **State labels**: one `StateLabel` family — TESTNET · REAL MONEY · PRACTICE (S3) · the confirmation tier (tap · Face ID · step-up, S14) · live voice state.
- **Status**: a quiet degraded banner per dependency per network (S8) and a "checking N pending…" banner on reopen (S7) share the context-banner grammar of the testnet strip.
- **Needs-you badge** on the dock's Activity item and the inbox bell count in the header (S23, J1).

## The identity brief

**One line:** electric lime on ink, silver objects that catch light, and real logos — money that moves when you speak.

**Stage and surfaces**
- Ink: `#0B0C10` background; raised `#14161C`; card `#191C24`; hairline `#262A34`. Textured black cards (a moiré/stipple wave, Solflare S15) for balances and receipts, drawn with a Skia shader on native and an SVG pattern on web.
- Lime: `#D4FF3A` (primary action, active dock item, live states); text on lime `#0B0C10`. Lime is loud, so it is rationed: one primary action per screen, the active dock bubble, the listening ring. Never for errors.
- Ink text `#F4F5F7`, muted `#A0A6B4`; success is **mint** `#35D39B` (so lime stays exclusive to action + live state); error `#FF5C5C` (never the accent); links white.
- Testnet layer (D15): the existing **sky** hue (`#4CC2FF` dark / `#0A6AAB` light) stays — it is further from lime and from red than amber would be, and the `testnet` / `testnet-dark` theme names and `ThemeSync` keep working. Strip + chip ("Testnet · no real money"); mainnet has no strip. Abu's "paper money" remark from the other project is the same idea: the toggle must be one tap and unmistakable.
- Light theme: paper `#F7F8F4`, cards white, text `#101210`. Lime cannot be text on white (≈1.9:1), so on light the **primary button is ink with lime text**, lime appears only as a fill under ink text, and the accent/ring/link colour is olive `#3F6600` (≈6:1). Full second theme, checked by a committed contrast script (`packages/ui-tokens/check-contrast.mjs` — the Stage 2 check was never committed).
- New semantic tokens in all four themes: `glass`, `glass-border`, `scrim`, `texture`, `silver`, `silver-deep`; `orb.mainnet` → lime triplet; `story.fields` exported to `tokens.ts` only. Motion durations live in `packages/config/src/motion.ts` (lint's `no-magic-numbers`).
- Colour fields for onboarding panels only: lime `#D4FF3A`, periwinkle `#7C8CFF`, mint `#8CF2C9`, coral `#FF7D6B`, ice `#DCE4F5` — each panel's rounded canvas is one field with ink text; the app itself stays ink.
- Exact hex values are proposals until the contrast script and the board say so; the relationships (rationed lime, mint success, sky testnet, olive on light) are the decision.
- Real logos keep their own colours (USDC blue, ETH grey, Base blue, Apple black/white, Google multicolour on light surfaces, monochrome white variants in dense lists like Fomo F21). Nothing is tinted lime.

**Type** (proposal): display **Space Grotesk** 700 (bold geometric, close to the references' hierarchy; replaces Bricolage Grotesque), body **Manrope** (kept; covers Latin + Cyrillic), figures **JetBrains Mono** (kept). Same Noto fallbacks on web; system script fonts on native.

**Materials and original artwork** (Kawase objects, not the references' mascots):
- **Koban coin** — an oval Edo-style gold/silver coin stamped 為替, ridged edge, reflective: the money object (balance, receipt, faucet).
- **Hanko seal** — a red-ink stamp reading 為替: "your approval" (allowance, Face ID, completion).
- **Paper plane** in brushed silver — send.
- **Glass orb** — the voice symbol, re-made: a beveled glass sphere with a lime light inside that brightens with the voice level; sits in the dock; fills the screen behind a blur when listening.
- **QR tile** — dotted QR that assembles from particles (S21/M04), with the Arc mark at the centre.
- **Silver flag** with 為替 for "you're all set" (S13/M18-style cloth).
- Technique: Solflare's "silver" objects are not photoreal chrome — they are **stippled / engraved monochrome renders** (halftone dots and etched lines that read as metal; visible on the piggy bank S04, the shield S02, the flag S13). That style is reproducible without a 3D pipeline: SVG layers with a dot-pattern fill whose dot size follows a light gradient (a Skia shader on native, an SVG `<pattern>` + mask on web), silver = ink dots on a pale disc, gold koban = the same in warm tones. It also prints well as a static frame and matches the textured balance card, so the whole app shares one material language.
- Production: vector/Skia first (SVG layers + Skia highlights so they run on both platforms, loop, and respect reduced motion); a Codex prompt for rendered hero images/loops if Abu wants photoreal materials later. Each object gets a brief (layers, materials, loop seam, still frame) in `plan/design/artwork/`.

**Brand identity deliverables** (the references all carry their own mark into the dock centre, splash, QR centre and share cards; Kawase has none yet — the app icon and splash are still Expo defaults):
- **Kawase mark**: 為替 set in a rounded ink tile with a lime accent stroke (the seal impression), plus a mono variant; **wordmark** "Kawase" in the display face with 為替 as the eyebrow. Used in the dock centre (behind the orb when idle), the story's last panel, the completion flag, the share-card frame, docs and landing (Stage 14/15).
- **App icon** (iOS 1024, Android adaptive foreground/background/monochrome), **splash** (ink + mark, both modes, `app.json`), **web favicon + PWA manifest icons + theme colour**, **push notification icon** (Android mono), **share-card frame** (Stage 12 renders receipts into it), **default avatars** (five koban silhouettes in tinted discs, chosen by user id).
- Files: `apps/mobile/assets/brand/*`, `app.json` (`icon`, `splash`, `android.adaptiveIcon`, `notification.icon`, `web.favicon`), `packages/identity/svg/kawase*.svg` (the mark is registered like any entity, `provider:kawase`).

**Page grammar borrowed from the references** (so every screen is built the same way):
- *Pushed page* (P02, P05, F18): back chevron in a dim circle, a small illustration top-start, a large display heading, a muted one-line subtitle, then content; the primary action is fixed above the keyboard.
- *Method list* (P02, S07, F20, F28): full-width rounded rows, leading functional icon or trailing real provider mark, one dominant row, "or" divider before social options.
- *Amount ticket* (F23/F24, P18): the amount alone, huge, dim while zero; preset chips; a custom keypad; **the primary button carries the validation state** ("$5 minimum", "Above your allowance — Face ID") instead of a separate error line.
- *Field with a state slot* (P05–P08, F04/F05): prefix (`@`) inside the field, clear button, a fixed-height line under the field for checking / error (× red) / available (✓ green), the button dims until valid.
- *List row* (F10, F12, F22): entity mark 44 px (real artwork, verified badge as a separate overlay), title + muted sub-line, amount right-aligned in mono, change/status coloured; skeleton rows (P13) while loading; an inline error row with Retry (P12) on failure.
- *Sheet* (P21, F08, F20): grab handle, title, optional subtitle, dim scrim, content-sized; tall sheets for detail (F13), nested child with an explicit back chevron (F28).
- *Context banner* (P11 "You are currently in Testnet Mode"): an info row at the top of the page — Kawase's testnet strip.

## Identity packet (real logos)

New package `packages/identity` (client-safe): `svg/` sources (one file per entity + variant), `PROVENANCE.md` (per file: first-party source URL, retrieval date, licence/usage note, sha256), `build.mjs` (`@svgr/core` → `src/generated/native/*.tsx` on react-native-svg and `src/generated/web/*.tsx` on the DOM — same pattern as `ui-tokens/build.mjs`, no Metro transformer), `src/registry.ts`, `src/index.ts`. Keys follow the study's asset-delivery contract: `chain:eip155:<chainId>`, `token:eip155:<chainId>:<lowercase address>`, `provider:<slug>`, `venue:<slug>`; chain ids and token addresses are imported from `packages/networks` (`NETWORKS`, `SHARED_ADDRESSES`, `NETWORK_ADDRESSES`) so the registry cannot drift from the verified addresses. Entry: `id, kind, name, symbol?, chainId?, address?, decimals?, brandColor, shape ('disc'|'uncontained'), marks { color, mono? (currentColor), wordmark? }, source`. Lookups `getChainIdentity`, `getTokenIdentity` (case-insensitive), `getProviderIdentity`.

Entities now: USDC and EURC on Arc mainnet + testnet; Arc (5042) and Arc Testnet (5042002) share the mark with explicit environment text; the CCTP V2 / App Kit source chains Ethereum, Base, Arbitrum, Polygon PoS, Avalanche, OP Mainnet, Unichain, Solana (bridge source only, capability-gated), testnet counterparts reuse the mark + "Testnet"; providers Apple, Google, Circle. Registered now, marks later: USYC, cirBTC, WETH (Stage 6), venues (CCTP/App Kit, LI.FI, Across, Relay, deBridge, Socket) and name services (ENS, Basenames, ArcNS). Nothing else until a Stage 6 route actually lists it.

`<Mark entity size variant chainBadge?>` twins in `ui-native` (used by the app on both platforms, since the web build is react-native-web) and `ui-web` (docs/landing/gallery): skeleton while loading, a neutral labelled disc on an unknown id, never a fake logo, never a Lucide icon. Roles stay separate: asset mark ≠ chain badge ≠ status chip ≠ avatar. Sources: first-party brand kits only (Circle/Arc, Ethereum Foundation, Base, Arbitrum Foundation, Polygon Labs, Avalanche, Optimism, Uniswap Labs, Solana Foundation, Apple HIG, Google sign-in branding). The study's crops are evidence only.

## The checklist every screen passes (so no body flow is forgotten)

**Account states:** guest (home with step 0 "Create your account"; any money action opens the sign-in sheet; guest data moves on sign-in via the existing merge) · new account (handle → setup → allowance → completion) · returning account (sign-in → home; the handle step is skipped when set) · expired session (a re-auth sheet over the current page, values retained) · sign-out (→ the story) · wallet not set up on this network (first-steps row + the stepper) · allowance revoked (Wallet & limits shows "off", the confirm card says Face ID for everything).

**Data states:** loading (skeletons, never spinners on rows) · empty (illustrated, with the next action) · error (inline row + Retry, problem codes mapped to copy in `errors.*`) · stale/offline (a quiet banner, cached values stay visible) · pending / confirmed / reverted / unknown-outcome for anything that moves money (the money-ending taxonomy, one chip family) · "coming" per network from `GET /capabilities` (F21-style badge with the reason).

**Network states:** testnet (strip + chip + "Arc Testnet" in every identity row; test USDC labelled as such) · mainnet (no strip; **REAL MONEY** eyebrow via `StateLabel` on every money card and sheet) · the switch itself (one tap; the first-mainnet consent sheet; the same address on both; every screen re-renders from `user.activeNetwork` with no wrong-network flash).

**Platforms:** iOS (Dynamic Island + home indicator clearance for the dock, Liquid Glass on 26+, blur below) · Android (`dimezisBlurView`, adaptive icon, edge-to-edge, navigation-bar colour per theme, hardware back closes overlay → sheet → page in that order) · web (server-rendered shell: `Platform` guards for Skia/blur/glass, backdrop-filter, keyboard navigation and focus rings, PWA manifest, the sign-in sheet's honest state) · desktop widths ≥ 900 px (the dock's rail orientation, a max content width; the full layout is Stage 13).

**Accessibility:** VoiceOver/TalkBack labels on every `Mark` (the entity's name), the orb ("Voice, listening"), the fan items and the dock; dynamic type to XL without clipping (rows wrap, amounts shrink with `adjustsFontSizeToFit`); 44 pt targets; reduced motion = still frames, instant overlays, unchanged hold time; colour never the only signal (network and status always have text); focus order on web; screen-reader double-tap counts for hold-to-confirm.

**Language:** every string in all ten catalogs; RTL screenshots of every screen (fan column, dock bubble, QR/addresses LTR, `StateLabel` for uncased scripts); each language listed in its own name and script.

**Performance:** Skia canvases load lazily per route; one blur layer at a time; the fan and dock at 60 fps on a mid-range Android (measured with the perf monitor); art as vectors, images ≤ 200 KB; the textured card's shader is static after first paint.

## Calls made in this plan (veto at the board gate)
- **Display font: Space Grotesk.** Bricolage Grotesque's quirks read as "editorial"; the references' hierarchy is bold, plain and geometric, which Space Grotesk gives without looking like Inter. Manrope and JetBrains Mono stay.
- **Artwork: vector/Skia by Claude first**, in the stipple/engraving technique, so every object ships in both platforms with loops and still frames. A Codex prompt for photoreal hero renders is written only if Abu wants the extra sheen after seeing the board — rendered PNG loops would be web-only and heavy.
- **Themes: both tokenised in Phase A, dark polished first** (the app's default), light brought to the same standard in Phase E with the same contrast checks — light gets the paper surface and the darker lime rather than a naive inversion.
- **Handle rules:** 3–20 characters, lowercase letters/digits/underscore, case-insensitive uniqueness, a reserved list (kawase, arc, circle, usdc, admin, support…), changeable in Settings; not shown to other users until contacts exist (Stage 5).
